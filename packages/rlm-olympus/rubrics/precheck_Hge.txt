You are evaluating a test patches for the following this rubric:

A valid test patch must meet these technical requirements:

## Critical Requirements:

**Valid Git Diff Format**
- MUST be valid unified diff format (git diff output)
- ERROR if not valid git diff format
- ERROR if patch is empty or contains only whitespace
- Each file change must have proper diff headers (--- a/path, +++ b/path)
- New files must start with --- /dev/null
- Binary files may appear as a diff header followed by "GIT binary patch" and a "[binary payload omitted: ...]" marker. The payload was hidden from review on purpose — this is a VALID binary diff; do NOT flag it as invalid, malformed, or empty

**test.sh File Requirements**
- This section talks about /test.sh at the repository root, it's possible the repo contains other files called test.sh, do not apply this check to those files
- MUST include a test.sh file
- ERROR if no test.sh or test runner file is present
- MUST support two distinct modes:
  - \`base\` mode: Runs existing/baseline tests (should pass at base commit)
  - \`new\` mode: Runs only newly added tests (should fail before solution)
- ERROR if test.sh doesn't support both base and new modes
- WARN if base and new modes run the same tests (defeats the purpose)
- When evaluating if modes run distinct test sets:
  - CAREFULLY examine test selection/deselection flags (--deselect, -k, --ignore, etc.)
  - Check if newly added test classes/functions are excluded from base mode
  - Compare what the patch ADDS to test files with what base/new modes actually run
  - If base mode excludes (or does not include) the newly added tests and new mode includes them, that's great
- SHOULD be executable (file mode 100755 in diff)
- WARN if test.sh is not executable (mode 100644 instead of 100755)
- The script should have clear case/switch logic for base vs new
- Should return appropriate exit codes (0 for success, non-zero for failure)
